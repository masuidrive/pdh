色 — 有彩は 3 つの役割にだけ使う

地と字が 6 色、有彩色は役割 3 つ ×（濃・淡）だけ。濃色は字と線とバッジに、淡色は小さな面の地にだけ使い、装飾には使わない。部品はこの token 名でしか色を参照しない（「5% 以下」のような測れない数値は規則にしない）。

--bg
ページの地
--paper
カード・本文の紙
--fill
紙の上の塗り
--ink
本文の字
--muted
補足の字
--line
罫線
--accent
判断・選択・接続
--accent-soft
選択中の地
--ok
推奨・合格
--ok-soft
推奨の地
--warn
注意・未測定・停止
--warn-soft
注意の地
寸法の token

--measure: 44rem（本文幅の唯一の基準）・--u: .25rem（余白の目盛）・--r: 6px（角丸）。部品が幅や余白のリテラル値を持つことを禁じ、検査は「token を経由しない hex / px が無いか」の grep 1 本にする。

部品 — 規則との対応つき

summary-grid

実装する規則: 決定サマリー 5 行（1 行目は対象の名指し。判断の番号だけの行にしない）。1 行目だけ全幅 + accent 枠で「何の話か」を最初に固定し、残り 4 枚は 4 列 → 2×2 → 1 列の固定段で端数を出さない。

今回決めること実行結果 JSON の Simple 表示で、複数キー object の親子関係を読める表示契約を A〜D から 1 つ選ぶ。
推奨A — Simple の用途を残し、brace と字下げで object 境界を示す。
確かめた事実現在の Simple は複数キー object を平坦化する。共有範囲は 5 component・6 呼び出し箇所。
まだ確かめられないこと実装後の 390px / 1440px × light / dark の実表示。
実装を止める条件選んだ案に API・保存データ・画面別 renderer 分岐が必要になる場合。

toc-rail（折りたたみ sidebar）

実装する規則: 読み手が現在地を失わない・未回答の判断を明示する（回答済みの判断に ✓ が付く）。広い画面では左に sticky、狭い画面では右上に浮いた「目次」ボタンだけを置き、押すと dropdown で開く — 帯を作らないので heading と高さを取り合わない。このページの左（狭ければ上）にあるのが実物 — 見出しを通過すると現在地が動く。節見出し（h2）も sticky で上に残り、いまどの節を読んでいるかが常に見える。

chips（主線ナビ）

実装する規則: 主線の固定 5 面 + 判断 + 返す。読み手が現在地を失わず、面へ 1 手で跳べる。

  • なぜ
  • ゴール
  • 解き方
  • 決めること
  • 判断 1
  • 返す

facts（語 + 説明の行）

実装する規則: 主語と目的語を省かない・経緯を 5 行で（元の問題 / やろうとした / 起きたこと / いまの状態 / 限界）。

元の問題
実行結果の JSON が入れ子のとき、どの key がどの object に属するか画面から読めない。
いまの状態
表示形式は未決。A〜D の 4 案と各案の AC を用意済み。
限界
実装後の実表示は未測定。実装前に測る手段が無い。

card-grid（端数を伸ばす）

実装する規則: 幅の基準は 1 つ。列数は幅で 3 → 2 → 1 と変わり、どの列数でも端数の 1 枚が伸びて右端が揃う — 「1 枚だけ孤立して段差」を部品側で潰す。

同じ共有範囲

5 component・6 呼び出し箇所が 1 つの表示契約を使う。

同じ入力保護

画像値の除外と 64 文字以上の base64 短縮を全案に適用する。

データ契約は不変

backend・DB・API・SDK・CLI は変更しない。

同じ表示検査

390px / 1440px × light / dark と、改行なし 512 文字で横 overflow を確認する。

callout（tone = accent / ok / warn）

実装する規則: 事実の確度を書き分ける（未測定は warn）・停止条件を目立たせる。色に意味が 1 対 1 で対応し、飾りには使わない。

未測定

実装後の狭幅表示は測定できていない。390px で横 overflow が出たら実装を止める。

推奨

A — Simple の用途を残して brace と字下げを戻す。

mock-frame（出来上がりの像）

実装する規則: 「出来上がりの像」欄 — 同じ入力 1 件・案名の明記・試作バッジ・変更前（現在）の基準を並べる。部品がラベルとバッジを持つので、忘れると枠ごと無いことが見える。

全案で使う同じ入力: {"output": {"display": {"overall": {"status": "ok", "score": 0.9}}}, "version": 2}

現在（基準）実画面
display
overall
status ok
score 0.9
A の完成像試作
{
  display: {
    overall: {
      status: ok,
      score: 0.9
    }
  }
}
C の完成像試作
{
  "output": {
    "display": { … }
  },
  "version": 2
}

tw（表）と acrow（AC 行）

実装する規則: 表を使うのはセルが語・数値・1 句で終わる列挙だけ。セルに文章を書き始めたらそれは表ではない — 語+説明は facts、案の比較は compare（セルは 1 文まで）、それ以外は本文の散文へ。表は読み手が検算できる形にし、自分の枠でだけ横に逃がす。AC は書き換えの隣で原文を確認できる。

fold（裏付けの折りたたみ）

実装する規則: 実測の全表・退けた案の詳細・経緯は主線から 1 手で開ける裏付けへ。

数値の由来 — 最大 10 回・depth 5・64 文字

最大 10 回と depth 5 は現行 Simple の上限を維持。64 文字は現行の base64 短縮条件で、この判断では変えない。

steps（順番のある列挙）

実装する規則: 順番が意味を持つときだけ使う — 段階承認の依存順・承認後の流れ・確認手順。順序の無い列挙は card-grid か facts（番号を装飾にしない）。分岐する流れは部品にせず mermaid に任せ、直線だけを steps で組む。

  1. グループ 1 — 表示契約承認済み（2026-08-18）。この board の判断はここに属する
  2. グループ 2 — 保存形式いま承認を求めている段階。グループ 1 の選択に依存する
  3. グループ 3 — 移行手順未着手。グループ 2 が決まると選択肢が 2 つに絞られる

timeline（経緯）

実装する規則: 経緯は「元の問題 → やろうとした → 起きたこと」を時系列で。1 行 = 事実 1 つ、日付必須。警告色は事故・症状の時点だけに使う。

  • 2026-08-12利用開発者から「複数キー object の親子関係が読めない」と報告
  • 2026-08-14Simple 表示の平坦化が原因と特定。表示契約の候補を 3 案作成
  • 2026-08-19この board を発行。判断 1 で表示契約を選ぶ

compare（案の横並び比較）

実装する規則: 軸は「利用者から見て / コスト / 取り返し」に固定して横に比べる（案ごとに違う観点で書くと比較できない）。推奨列だけ accent-soft、3 案まで — 4 案以上は判断カードの縦積みへ。表は tw と同じく自分の枠内でだけ横に逃がす。

A. brace・comma・字下げを戻す推奨C. Simple を廃止して Raw だけ
利用者から見て親子関係が読める。全体は有効な JSON にならない常に有効な JSON。抽出・省略・型別色を失う
コスト表示層のみ・実装小実装は減るが利用者の読む手間が増える
取り返し表示契約だけなので後から選び直せる同じく選び直せる

quote（出典つき引用）

実装する規則: 報告・発言は要約で潰さず原文で引用し、出典（誰・どこ・いつ）を必ず付ける。症状の言い換えは原因の先取りになるため、判断の起点は原文で見せる。

実行結果の JSON で、object の中身がフラットに並んでいて、どのキーがどの階層のものか分からなくなっています。

利用開発者の報告 · 開発チャンネル · 2026-08-12

fig（画像・SVG 図・flowchart）

実装する規則: 確かめてほしいケースは 1 件残らず画面写真にする・caption には「この図の何を見てほしいか」（満たすべき条件）を書く・撮る前は寸法入りの枠を置く。分岐・依存は文章より図 — 矢印を引こうとすると、引けない矢印が目に見える。SVG の色は token を参照し、明暗テーマに追従する。

判断カード + option（回答は kit/board.js の契約）

実装する規則: 判断カードの型（背景 / 推奨 1 行 / 覆す条件 / 選択肢の 5 欄）と approve or direct。選択・集計・貼り戻しの動作は kit/board.js が持ち、このページは見た目だけ。

判断 1 — Simple の表示形式をどれにするか？

背景: 複数キー object の平坦化で親子関係が読めない、という報告から。

推奨: A — Simple の用途を残し、brace と字下げで object 境界を示す。
覆す条件: Simple の機能より「値全体を 1 つの有効な JSON で表示」を優先するなら C。

answer（返す）

実装する規則: 選択内容をそのまま返せる文章と返し先。集計・コピー・復元は kit/board.js。
