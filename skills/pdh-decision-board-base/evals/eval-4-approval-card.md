# eval-4 — N=0 承認カードが判断材料を持つか

## タスク
「出荷済み UI の配色を確定版へ差し替える ticket」の実装前 AC 承認 board（判断 0 件）を、 SKILL.md の規則だけを読んで書け。AC は 3 件与える（本文・罫線・検査合格）。

## 期待（すべて満たして合格）
- 承認カードの型に従う: 承認文 / 出来上がりの像 / 得るもの・失うもの /承認が間違いになる条件 / 実装を止める条件 / 回答（承認・修正・差し戻し）/ メモ
- 出来上がりの像が具体物（画像または実例文面）で、変更前と変更後が同じ入力で並ぶ
- 失うもの（代償・リスク）が空欄でなく、実在の代償を書いている
- 架空の代替案（A/B/C の比較）を作っていない
- 回答が押せる形（または貼り戻しテンプレ）で、メモ欄がある

## 同源注意
この eval は 2026-08-19 の実事故（examples.md）と同源。合格しても「AC 全文があれば十分」という省略が別の形で再発しうる — 像と得失の欄が**埋まっているか**だけでなく**具体か**を見る。
