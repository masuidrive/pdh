# eval-3 — 決定サマリーの推奨を 1 行にできるか

再現する失敗: 決定サマリーの推奨行に選択肢 A の契約全文(約 200 字)を詰め込み、承認者が 1 ページ目でその 1 文を解読することになった。同じ契約文は判断カードの選択肢 A にも全文あった(逐語の重複)。reviewer は「用語と数値を一文に詰め込みすぎ」と指摘したが、言い回しの問題として採られなかった。

## 読ませるもの

`SKILL.md`

## 入力

判断は 1 件。実行結果の JSON 表示(Rendered 表示)の契約を決める。

- 選択肢 A(書き手の推奨): caller は結果 object(wrapper)全体を渡し、renderer が output を表示対象にする。depth 0〜4 の複数キー object に brace・comma・1rem 字下げを戻す。 plain string は quote しない。64kb を超える value は truncate する。
- 選択肢 B: 現行の表示(brace・comma 無し)を保ち、raw タブだけに JSON を出す。

## タスク

この board の決定サマリー(5 行)と、判断 1 の判断カード(選択肢 A・B を含む全体)を書け。

## expected_behavior

- [ ] サマリーの推奨行は「どの案を選ぶか + 理由 1 行」に収まっている(契約の列挙が無い)
- [ ] 契約の全文は判断カードの選択肢 A に 1 回だけ現れる(サマリーと逐語重複しない)
- [ ] 決定サマリーが 5 行の構成(決めること/推奨/確かめた事実/未確認/停止条件)に従う
- [ ] サマリー 1 行目が「実行結果の JSON 表示」という対象を名指しする(「判断1で選ぶ」のようなメタ情報だけにしない)
- [ ] 推奨を覆す条件が判断カードにある
- [ ] 選択肢 B にも A と同じ精度の記述がある(薄く書いて誘導しない)
- [ ] 各選択肢に「出来上がりの像」がある — 同じ入力 1 件を使った表示結果の具体物(UI なら試作画面、最低でも実例の文面)。文章の説明だけで済ませていない
- [ ] A と B の像が同じ入力・同じ画角でそろい、どの像がどの案かが像の隣に明記され、変更前(現在)の像も基準として並ぶ
