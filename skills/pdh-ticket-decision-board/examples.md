# 日付つき事故・実測
このファイルは、判断ボード規則の根拠になった事故と実測を保存する事例集である。
通常は読まず、規則の理由、既定値の由来、過去の再発形を調べるときだけ読む。

## 2026-08-12 — 調査前の推奨は、札を付けても正しくならない

サンプル board は「8 分に届く」を見込みのまま示し、別案へ「先に測らせる — 約 30 分」を置いた。
board 自身が 30 分で測れると書いていたため、これは実装後にしか分からない不確実性ではなかった。
**測れる項目は board の前に測り、測定を承認者への選択肢にしない**という規則になった。

同じ board は「削除対象 7 件が規則の不備から生まれた」を `推論` とした。`git log -S` で追うと、
7 件のうち 4 件はその規則より前に存在し、推奨の中心が部分的に否定された。`推論` のラベルは
調査を省く許可ではなく、調査しても実証できない主張だけに使う。

## 2026-08-12 — 数は集合と条件を持たないと誤読される

外部 reviewer は、次の不整合を指摘した。

- 「7 件を削除・統合する」と書いたが、7 件を 1 件ずつ復元できなかった。
- 1 件が準備だけで `5.12 秒`かかる例を、全体の見積もりとして読める位置に置いた。
- 全体 `17.5 分`と、複数の内訳を並べたが、並列か直列かを書かなかった。
- `10 分 / 8 分 / 5 分`の目標に、各処置の寄与を積み上げなかった。
- `15 分 08 秒`は別処理の並走中、`8 分以下`は単独実行であり、比較条件が違った。
- `171±2`という AC は、対象 7 件を処理しなくても数値だけ満たせる緩い条件だった。

この事故から、集合の再集計、同条件比較、合計と内訳の関係、目標の積み上げ、緩い AC の明示を
別々に検査するようになった。

## 2026-08-12 — reviewer 用の抽出が board の欠陥を作った

HTML をテキストへ抽出して reviewer に渡したところ、抽出処理が強調を落とした。reviewer は
「拾い読みで筋が通らない」を 6 回連続で返したが、どこまでが元の board の欠陥かを分離できなかった。
**承認者へ渡す形を加工せず reviewer へ渡す**という規則になった。

## 2026-08-12 — 狭い画面の空白と横 overflow

sticky 見出しの背景を擬似要素の `inset: 0 -50vw` で広げた HTML 文書を Galaxy Z Fold 7 で開くと、
幅 `380px` の条件で `scrollWidth = 527`、`clientWidth = 365` になった。擬似要素の絶対配置が scroll
範囲へ加算されていた。`box-shadow` へ変えると配置範囲を増やさず背景を伸ばせた。

当時は文書を `344px` から `1600px` まで測った。汎用 renderer では特定端末名を規則にせず、
プロジェクトの最小・最大 viewport を使う。`380px` は、設定がないときの実測由来の狭幅目安として残した。

## 2026-08-12 — 暗色テーマの強調

斜め読みの帯を半透明で置いたところ、暗い背景では alpha `.30` が見えず、`.45` で識別できた。
切替後の見た目だけでなく、`--hl` の計算値が明暗間で違うことを確認する規則になった。

## 2026-08-12 — 表の結合を外すだけでは数を復元できない

複数行へまたがる処置を `rowspan` で示していた表から結合を外し、セルを短くした。外部 reviewer は
表を 2 通りに読み、片方では board の件数と合わなかった。`rowspan` の使用可否ではなく、
**表だけで主張する数を復元できるか**を規則にした。

## 2026-08-12 — 初出の語と数

試作には「約 580 / 約 335 / 約 246 箇所」が何を数えた数字か書かれていなかった。並走 ticket は
ID だけで示し、規約は番号だけで指した。読み手がその場で意味を復元できるよう、初出の固有名詞と
数には対象を添え、規約は判断に必要な本文を示す規則になった。

## 2026-08-13 — 実際の実行条件で推奨が反転した

テスト所要を 1 本ずつ単独で測ると、絞り込みは `82 秒`の損に見えた。board は 9 周のあいだ
「短縮は並列実行から出る。絞り込みからは出ない」とした。しかし実際の `test-all.sh` は 2 本を
同時実行していた。同じ形で測ると絞り込みは `85 秒`の得になり、推奨が反転した。

この repo では測定条件を「2 本同時・各 7 並列 — 実行入口と同じ形」のように書く必要があった。
`test-all.sh` や PostgreSQL は汎用規則ではなく、この事例の具体名として残す。

## 2026-08-13 — repo の語彙は実在検索で判定する

ある board では `backend (PostgreSQL) leg` が repo の規約に実在したため、そのまま使えた。
一方 `PG leg` は repo のどこにも存在しない略語だった。固有語を日本語へ言い換えることではなく、
**対象 repo に実在する語かを検索する**ことを判定法にした。

## 2026-08-13 — 文書の本文幅を面全体へ誤適用した

本文 1 行の既定 `46em` を面の箱全体へ適用したため、`40px` の見出しが 18 字で折り返し、画面の
半分しか使わなかった。本文幅は目で追う散文のための規則であり、見出し、表、カードには当てない。

半角識別子の `logs.spec.ts:476` が混ざる日本語では、`38em` だと日本語相当の密度が 30 字を割った。
反復調整の結果として `46em` を既定に残したが、実測された普遍的な読字限界とは扱わない。

## 2026-08-13 — 規則の目的を忘れて逆効果にした

同じ日に次の誤適用が起きた。

| 覚えていた規則 | 守る対象 | 誤適用 |
|---|---|---|
| `rowspan` で結合しない | 数を復元できること | 結合を外して数を復元不能にした |
| 1 行は `46em` | 目が行を取り違えないこと | 目で追わない見出しへ適用した |
| コードに日本語組版を当てない | ソースコードの文字位置を保つこと | 日本語散文を持つ `<pre>` から禁則まで外した |

規則を適用する前に、その規則が何を守るかを 1 文で言う手順を追加した。

## 2026-08-13 — 必要を確認しない class

一般名 `.num` を地図番号と数字カードの両方へ使い、地図の小さな数字がカード用の枠と padding を
拾った。別の箇所では `.lead` を念のため足したが、対象 18 件はすべて既存 selector で覆われ、
新しい class は 1 件も必要なかった。class は役割を名前に含め、追加前に必要な要素を数える。

## 2026-08-13 — 日本語の行頭禁則を目視で見落とした

6 成果物のうち 3 成果物に行頭禁則違反があったが、ユーザの指摘まで気づかなかった。
各文字の `Range` を測り、改行位置の禁止文字を数える検査を追加した。

## 2026-08-13 — 1 回の reviewer 結論だけで抜けた

9 周目の問 1 は「決められる」だったため、その時点で終了した。同じ回答の問 3 には、
次の事実不整合が 3 件あった。

- 所要時間が `1 分 41 秒`と`2 分 45 秒`で一致しない。
- 同じ AC が必須と任意の両方で書かれている。
- 測定本数が 6 本と 5 本の両方で書かれている。

問 1 と問 3 を別軸として扱い、問 1、3、5、6 と文の検査が 2 周連続で片付くことを標準 gate にした。

## 2026-08-13 — 文書を通った内容がデッキでは通らなかった

9 周かけて「決められる」になった HTML 文書と同じ内容からデッキを作ると、最初の review で
「決められない」が返った。13 項目の中身が後半まで出ず、重要な矛盾は縦の裏付けにあった。
デッキ review は、文書 review が見落とした表の合計と削除件数の算数誤りも見つけた。
媒体を変えたら、その媒体を独立して検査する規則になった。

## 2026-08-14 — 主線の長さ

判断が 3 件の board では、なぜ、ゴール、決めること、判断 3 件、返す、の **7 面**が主線になった。
同じ board を 16 面の時系列として並べた版は、判断より作業経緯を先に読ませていた。
この数字を規則にはせず、**固定 4 面 + 判断数**という式へ一般化した。

## 2026-08-14 — 合意済み画像を開かなかった

Extract API の回答案本文だけを読み、添付された変更前後の mockup を開かなかった。mockup が黄色の
注意として描いた警告を ticket では「警告色を使わない」と決め、上限変更の導線と画面文言でも
食い違った。画像を開き、画像が決める具体を文字へ起こし、異なる提案は判断として示す規則になった。

当時の ticket 固有例では `pdf / pptx` が位置情報を持ち、`xlsx / docx` は扱いが異なった。
これらは汎用規則ではなく、事実と調査経緯を分ける必要を示す事例である。

## 2026-08-14 — 選択肢と ticket が対応しなかった

独立 reviewer を 5 周行い、次の欠陥が繰り返し見つかった。

- 判断 1 が判断 2 の内容を変えるのに、判断 2 を先に選べた。
- `xlsx / docx` の抽出を書き直す案を選べたが、ticket の Out-of-scope は書き直しを禁じていた。
- AC を外す案を選べたが、ticket の確定判断はその AC の機能を必須にしていた。
- 選択肢で AC 件数が 7、8、9 と変わるのに、承認文は常に 9 件だった。
- 選択後に ticket のどの節を消すかが書かれていなかった。

選択肢ごとに ticket の変更先、変更後の件数、他節との整合、判断依存を確認する規則になった。

## 2026-08-14 — 回答を最後まで覚えさせた

複数判断の選択肢を最後にだけ置くと、読み手は判断結果を頭に保持して移動する必要があった。
材料直後と最後の両方へ同じ判断を表示し、`data-q` で状態を同期する形へ変えた。表示数ではなく
論理判断数を数え、`回答 2 / 3`と`●●○`を固定表示するようにした。

アプリ内ブラウザでは `navigator.clipboard` が失敗することがあり、失敗時に回答文を選択して
「長押しでコピー」と案内する fallback を追加した。横デッキでは `href="#…"` だけでは横へ
移動しないため、`scrollIntoView` を併用した。

## 2026-08-14 — 1 面に収まる検査が 3 回とも安全側へ誤った

最初は `.p { min-height: 100dvh }` に `scrollHeight > clientHeight` を使い、内容と一緒に
clientHeight が伸びたため 7 周のあいだ overflow 0 と報告した。測り直すと 23 面中 18 面が
viewport より高く、最大 `1.67 倍`だった。

次に `height: 100dvh` へ変えたが、flex child の `offsetHeight` が面高へ丸められた。内容が
`1982px`ある面で `offsetHeight = 844px`を返し、10 項目中 4 項目目以降が切れていた。

さらに高さだけを比較すると、内容全体が下へずれていても合格した。`transform-origin: center center`
では、`390 × 630` の面で内容が `172px`下へはみ出し、選択肢とメモ欄が画面外になった。

`scrollHeight` と下 padding、`center top`、上下端の位置比較、故意に壊す probe を組み合わせる
規則になった。情報を削らず面を 34 面へ分けると、基準超過は 1 面まで減った。

## 2026-08-14 — 自動縮小と responsive 既定値

`MIN = 0.72` は、それ以下では文字を読みにくかった実測由来の縮小下限である。下限へ達した面は
切らずに scroll させる。表をカードへ変える `760px`、地図の `threshold: 0.6`、狭幅検査の
`380px`も普遍値ではなく、renderer の初期値として使う実測由来の目安である。

## 2026-08-14 — 表の右側が見えなかった

5 列比較表の右 2 列にコストと取り返しを置いたが、`width: max-content` と nowrap のため画面外へ
切れた。読み手は横に続くことへ気づかなかった。狭い画面で 1 行 1 カードへ変え、header を JS で
`data-label` に写すようにした。

label を別行へ積むと cell が 2 行になり、固定 `5rem` の左列を作ると本文幅が減った。1 カードが
`230px`になり、5 行の表が画面の `2.3 倍`へ伸びた。label を同じ行へ inline にすると収まった。

## 2026-08-14 — AC 修正で複製箇所が古くなった

AC10 を「文面を入れる」へ変えたとき、5 つの popover と本文 4 か所が「草案を書く」のまま残った。
1 つの AC は board 内の **5〜9 か所**へ複製されうる。この件数を規則にはせず、AC 番号と
`pop-ac10-` のような安定した参照 ID で grep し、全箇所を出す規則にした。

別の修正では `1 分 41 秒`を含む 1 文だけを直し、同じ主張を別の言葉で書いた 2 か所が残った。
文章ではなく、数値、ファイル名、AC 番号を検索する理由になった。

## 2026-08-14 — 判断範囲を縮めても見出しが古いまま残った

「実装に入ってよいか」を判断対象から外し、「確認を 2 つ進めてよいか」へ縮めたが、AC 見出しと
返答文に「今すぐ実装してよい」が残った。表題、決定サマリー、推奨、承認見出し、返答文を一緒に
確認する規則になった。

## 2026-08-14 — 未定義 class と誤った class

`class="mut"` を書いたが `.mut` の定義がなかった。別のデッキでは文字へ `.hint` を使ったが、
`.hint` は全面へ矢印を置く `position: fixed` の層だった。ブラウザはどちらもエラーにしない。

さらに、部品 CSS を一時ファイルへ書いて使わず捨て、`@media` 内の上書きだけが残った。
タグ数、禁則、横 overflow はすべて緑でも、枠、2 段組、図は描画されなかった。class 定義の grep と
`getComputedStyle`、実画面の確認を分けた。

## 2026-08-14 — 正規表現が面をまたいだ

`<p class="claim">(.*?)</p>\s*<p class="lede">` の一括置換が、claim の直後に lede のない面から
次の面の lede までを 1 一致として飲み込み、面を 3 つ消した。置換前に一致数を確認し、置換後に
面 ID、見出し、地図枡、回答 ID の個数を比較する規則になった。
