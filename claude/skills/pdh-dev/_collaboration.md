# PDH Dev — ユーザ相談ルール

重大なsecurity問題を発見した場合はユーザに確認する。

相談では、何をしたか・何を達成したか・検証の証拠・判断点・選択肢（推奨案を先頭に）を説明し、各選択肢にtradeoffを1行添える。

相談条件に該当したらhuman review gateを待たず、noteに加えて会話で状況、判断、選択肢を示す。

## 設問には番号を振る

守るのは **ユーザが番号だけで答えられること** である。「T2 の 3 で」と書けば、どの設問のどの選択肢かが 1 つに決まる。番号が無いと、ユーザは選択肢の文言を引用して書き写すことになる。

- **設問は `T1` `T2` … と番号を付ける。**設問が 1 つでも `T1` を付ける — 後から 2 つ目が増えたときに番号を振り直さずに済む
- **選択肢は設問ごとに `1` から振る**（`T2` の選択肢も `1` から）。推奨があれば番号のあとに「（推奨）」と書く
- **番号は 1 つの返答の中で一意にする。**同じ返答で `T1` を 2 度使わない
- **対象は、ユーザの判断を求めるものすべて** — 会話、判断ボード、ticket の Open Questions、issue や PR のコメント。skill を読み込んでいない会話でも同じ（`PDH-AGENTS.md`「Reporting」が常時側の 1 行を持つ）
- **番号は単独で使わない。**`T1` だけを書かず、必ず設問文と一緒に出す（`pdh-decision-board` の `reader-profile.md`「番号を単独で使わない」）。番号は答えるための呼び名であって、設問の代わりではない
- 判断ボードでは、**設問の見出しと選択肢の `data-label` に番号を書く。**`data-q` は番号にしない — あちらは機構が判断を同定する安定 ID で、意味のある名前を持つ（`pdh-decision-board` の `html.md`「DOM 契約」）。**番号と `data-q` は寿命が違う**: 番号は返答ごとに振り直され、`data-q` は板の寿命を通じて変わらない
