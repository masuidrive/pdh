# 既定の読み手プロファイル

board を書く前と、発行前に読む。**`CLAUDE.local.md` の「読み手プロファイル」節に **【項目名】** があれば、その項目は既定を使わずそちらに従う**（項目単位。無い項目は既定のまま）。承認者ごとに profile が違うなら、その board の承認者のものを使う。**上書きできるのはこの分冊の項目だけ** — 承認・証拠・機微情報・不可逆操作の規則（base.md / risk-overlay.md）は読み手の好みで上書きしない。

«承認者が何で止まり、何なら決められるか» の既定で、base.md の一般規則をこの読み手像で具体化する。項目は **【名前】** で参照する。

## 読み方
- **【記憶前提にしない】** 前の board・前の面・承認者の前回の選択を覚えている前提で書かない。参照でなく内容そのものをその場に置く。
- **【選択はその場】** 選択は材料を読み終えたその場に要る。選択肢を末尾にまとめない。判断 1 件ごとに 材料 → 選択肢 で閉じる。
- **【覆す条件の位置】** 覆す条件と代償は、選択肢の直前か直後の見える位置に置く。裏付けの奥に隠さない。
- **【主線で閉じる】** 判断に要る材料を裏付けにしか置かない board は、その材料が無い board と同じ。主線だけで判断が閉じる。
- **【面を揃える】** 判断の面は同じ型で揃え、並べて見比べられる形にする。

## 画面（全媒体）
- **【1 面 1 判断】** 材料（症状・推奨の理由・覆す条件・決めないと起きること）を、読める大きさのまま収める。収まらないなら面を割るか材料を削る。材料の可読性を落として詰めない。
- **【進捗を見せる】** 進捗（回答 n / N）は常に見える位置に置く。
- **【表は列を絞る】** 表は狭い画面でカード積みに変わり縦に伸びる。列を絞る。

## 画面（HTML のとき）
- **【媒体】** HTML は 1 枚に文書とスライドを持ち、上のトグルで切り替える（`build.sh --layout combined`。html.md「1 枚に文書とスライドを持つ」）。既定表示は文書（読む操作は上下スクロールだけ）。スライドは狭い画面のとき開く。回答は同じ判断 ID で両表示が共有する。粒度は揃えなくてよい（スライド＝決めるのに要る結論、文書＝根拠）。スライドで落とした材料が文書にあることは確かめる。
- **【回答バーの位置】** 回答数（進捗）と選択の UI は kit が置く（広い画面では右上のバッジ、狭い画面では下端へ移す）。**板の作者は位置を指定せず、下部バーや「前 / 次」を自作しない**（deck の移動は 4 辺クリックで、前 / 次の部品は無い）。発行先のヘッダーが右上のバッジを隠すなら、それは発行先側の設定であって板の材料ではない。
- Markdown・端末・PR コメントを選ぶときは、この HTML 固有の 2 項目は当てない（base.md「媒体を選ぶ」に従う）。

## 語
- **【実体の名前】** 実体の名前で書く。言い換えを避けるのは repo 固有の内部ラベルだけで、パス・コマンド・ツール名・一般技術語（git push / CI / API / JSON）はそのまま書く。
- **【略語を開く】** 自作の略語・熟語は開いて書く。
- **【番号を単独で使わない】** `#n`・`ACn`・「判断 n」を単独で使わない。初出に 1 行の説明を添えるか、押して開く定義を付ける。
- **【ID で参照しない】** ID（ticket ID・会話 ID）で参照しない。症状で説明する。

## 文
- **【主語目的語】** 主語と目的語を落とさない。見出し・タイトル・1 行の推奨から真っ先に落ちる。比喩の動詞（運ぶ・効く・回す）と、指示対象の無い抽象名詞（もの・こと）を疑う。
- **【N をならべる】** 「N 点ある」「N 件ある」と書くなら、その N 個を箇条書きにする。表はよい。
- **【契約を 1 文に詰めない】** 1 文に契約の全文を詰めない。

## 像
- **【像が要る判断】** 見た目で決める判断（画面の配置・操作の有無・出力の形）には、変更前と案ごとの見え方を示す像が要る（同じ入力・同じ幅・差が出る部位）。見た目に関わらない判断は文で足りる。
- 撮る主体と時期は base.md「出来上がりの像」に従う。**board を書く agent がブラウザを開けないなら、像も表示の実測も «回せない» として承認者へ渡す**（`PDH-AGENTS.md`「Browser And Surface Checks」）。自分で «撮った / 測った» と書かない。

## 順序
- **【なぜ→ゴール→判断】** なぜ → ゴール → 判断 → 返す。目的の 1 行を先頭に置く。経緯を主線に並べない。
- **【URL は末尾】** 会話で押す URL は末尾に置く。

## 選択肢
- **【推奨は 1 つ】** 推奨は 1 つ。案を対称に並べた比較表は提案ではない。
- **【選択肢は 3 つ】** 選択肢は 3 つを目安に。各案に 得るもの / 失うもの / 選ぶと起きること を 1 行ずつ改行して分ける。
- **【選択の印】** 選択中の印は、推奨バッジと選択操作の位置を取り違えない（推奨が選択済みに見えないように）。
- **【個別判断は 5 件まで】** 個別に選ばせる判断は 5 件まで。承認だけでも「承認する / しない」を押させる。

## 強調
- **【強調は密度×長さ】** 強調は密度と長さで決める。短い面なら多くても止まらない。長い本文で全部を強調しない。

## 発行前の自己検査

文で確かめる:
1. `#n`・`ACn`・「判断 n」・自作の略語を、説明なしに使っていないか
2. 見出しと 1 行の推奨に «誰が・何を» があるか
3. 「N 点ある」と書いた箇所が箇条書きか
4. 選択肢ごとに 得るもの / 失うもの / 選ぶと起きること があり、推奨は 1 つか
5. なぜ → ゴール → 判断 → 返す の順で、目的の 1 行が先頭にあるか
6. 判断に要る材料が裏付けにしか無い箇所が無いか

描画して確かめる（board を書く agent が描画できないなら «回せない» として渡す。自分で確認済みにしない）:
7. 材料が読める大きさで画面内に収まり、スクロールするのは選択肢だけか
8. 見た目で決める判断に、変更前 + 案ごとの像があるか（同じ入力・同じ幅・差が出る部位）
9. 進捗（回答 n / N）が常に見えるか
