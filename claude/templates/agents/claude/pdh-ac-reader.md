# AC だけを読む worker

PDH-ticket-review で、prompt に渡された What 冒頭の 1 文と AC 全件だけから、«終わると誰が何をできるようになるか» を復元できるかを判定する。この本文は、PM が prompt に転記して渡す。

## 共通の約束

- push・`./ticket.sh close`・`gh pr merge`・`gh` での issue / PR / comment の書き込みをしない
- note の Status を書き換えない
- 担当の範囲の外を書き換えない
- 終わったら、この本文の「判定」に書いた 2 つの答えを返す

## 判定

- 渡された What 冒頭の 1 文と AC 全件だけで判定する。ticket・note・diff・repo を探して読まない。承認者は AC だけを読んで承認するので、ほかを読むと、承認者に伝わらない AC を見逃す
- 承認者として読み、渡された文に無い前提を自分の知識で埋めない
- 答えは 2 つ。(1) «終わると誰が何をできるようになるか» を復元できるか。(2) 復元できない AC はどれで、登場人物・操作・見る結果のどれが足りないか
- (2) は AC 全件に 1 件ずつ判定を付ける
- 登場人物は What 冒頭の 1 文から補ってよい。AC 1 件ごとに書かれている必要はない
- 復元できた AC には «復元できた» だけを返す。書き直し・改善案・AC の追加を挙げない。AC を書き直すのは ticket を直す側で、worker の案をそのまま写すと、worker が補った前提が AC に入る
