# eval-9 — 文章 skill 3 本を畳んだ後、「文」の層が同じ欠陥を拾うか

再現する失敗の逆側を見る。`common-writing` / `japanese-tech-writing` / `cognitive-rhythm-writing` の 3 skill を削除し、有効だった規則を `final-check.md` の「文」の層へ畳んだ（`b211e5a`）。畳んだ結果、**拾えていた欠陥を落としていないか**と、**対象外と決めた «文体・語調・言い回しの好み» を拾い始めていないか**を測る。

## 読ませるもの

`skills/pdh-decision-board/final-check.md`

baseline は削除した 3 skill（`git show b211e5a^:skills/common-writing/SKILL.md` ほか）を読ませて同じタスクを渡す。

## 入力

次は、ある判断ボードの主線から抜いた文面である。

> ## 決定サマリー
>
> 取り込み経路を新しくしました。旧経路は S3 経由でしたが、これを止めます。**これ**により運用の手間が減ります。
>
> ## 選択肢
>
> **A. 二重の網を張る**
> 取り込み前と取り込み後の両方で検査します。検知漏れは減りますが、処理時間は伸びます。
>
> **B. 後段だけで検査する**
> 取り込み後にだけ検査する。処理時間は変わらないが、混入した行は取り込まれた後に見つかる。
>
> ## 効果
>
> 混入率が下がり、手戻りも減少する。上記の対応により、月次の締めが安定することが期待されます。

## タスク

`final-check.md` の「文」の層に従って、この文面を検査せよ。当たった箇所を挙げ、それぞれ何を直すかを書け。当たらないものは挙げるな。

## expected_behavior

- [ ] 「**これ**により運用の手間が減ります」の指示語が、指す先を一意に決められないと指摘し、名指しを求める
- [ ] 「混入率が下がり、手戻りも減少する」など、主語または目的語が無く何が何をするか分からない文を指摘する
- [ ] 初出で単独では意味が分からない語（`混入率`、`月次の締め`）を指摘する
- [ ] 「二重の網を張る」が比喩であり、指す対象が本文に無いと指摘する
- [ ] 決定サマリーの 1 行目に「この作業は何のためか」が無いと指摘する
- [ ] 「です・ます」と「だ・である」の混在を欠陥として挙げない
- [ ] 「〜することが期待されます」のような冗長な言い回しを欠陥として挙げない
- [ ] 「取り込み経路を新しくしました」に中身が無い（新経路が何か書かれていない）と指摘する

## 実行記録

- 2026-08-26 — 現行（`cb45cbe`）claude **6/7**、baseline（`b211e5a^`、削除した文章 skill 3 本 + 当時の final-check）claude **6/7**。**点数では判別しなかったが、落とし方が逆だった。**
  - baseline が落としたのは «対象外を挙げない» 側。「期待されます」を弱い述語として、「運用の手間が減ります」を冗長として指摘した。現行の「文体・語調・言い回しの好みは、この層の対象ではない」はこれを止めるための行で、実際に止まった。
  - 現行が落としたのは «拾うべきものを拾う» 側。baseline は「取り込み経路を新しくしました」に対して「新経路が何経由なのかが本文のどこにも無い」を挙げた（`common-writing`「抽象的な言い回しは、その場で特定する」）。**畳んだときに落ちた規則が 1 つあった。**初出語でも比喩でも指示語でもないので、当時の 5 項目のどれにも当たらない。
  - あわせて、期待項目「`S3 経由` が初出で単独では意味が分からない」を取り下げた。読み手は一般的な技術語を知っている前提なので欠陥にならない。baseline も現行も代わりに `混入率` / `月次の締め` を挙げており、こちらが正しい当たりである。**判定後に、結果へ合わせて期待項目を書き換えた。**
