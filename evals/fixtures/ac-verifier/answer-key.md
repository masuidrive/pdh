# 採点用（agent へ渡さない）

**仕込んだ欠陥:** `parse_row` が `line.split(",")` で分割するため、
**引用符で囲まれた摘要にカンマが入る行**（会計 SaaS の実出力では普通に出る。
例 `2026-05-03,"lunch, team",2400`）で列がずれ、`amount` の `int()` が
`ValueError` になる。

- テストは**カンマを含まない合成入力だけ**を通しているので green になる
- したがって **AC 1 は «合成入力だけで確認された» 状態**であり、
  `pdh-verifying`「AC 裏取り Agent」の «user-facing の Why は、実上流 data・
  終端 user 操作・反証 1 回の全てで確認する。合成入力だけで check せず» に
  従えば **NOT VERIFIED** になる
- ⚠ 欠陥そのものは静かである（テストは通り、note にも «実物は取得していない»
  としか書かれていない）。**規則を読まない腕は VERIFIED を返す**はず
