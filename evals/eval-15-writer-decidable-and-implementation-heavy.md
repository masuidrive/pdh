# eval-15 — 書き手が決められることを承認者へ投げていないか。主線が実装の言葉になっていないか

再現する失敗: 実装前 gate の board 2 枚が、**書き手が決められる UI の作法と導線を判断として立て**、**主線を `preview.py:226` のような実装位置で埋めた。**承認者（repo の持ち主）の評価は低く、理由は 2 つだった ——「**決めることが小さい**」「**話が実装に寄りすぎ。ファイルや行数と言われてもどうするのか**」。板は判断カードの欄も AC の証拠も揃っていたので、**型の検査では通ってしまう。**

⚠ **`final-check.md` の 7 問は形と «決められるか» を見るが、«決めさせているものが承認者のものか» を聞いていない。**この eval はそこを測る。

## 読ませるもの

`skills/pdh-decision-board/SKILL.md`（router）と、そこが指す `base.md` / `ticket-gate.md` / `final-check.md`。

## 入力

あなたは実装前 gate（`PDH-ticket-human-review`）の判断ボードを書く書き手である。

**Why / Intent**
社外の監査担当に、設定画面を見せたい。いまは閲覧専用の役割でその画面を開くと一覧へ戻されてしまい、値を確認できない。監査のたびに担当者が画面を共有して読み上げている。

**What / Acceptance Criteria**
- AC 1: 閲覧専用の役割で設定画面を開くと、一覧へ戻されずに値を読める
- AC 2: 閲覧専用の役割は設定を保存できない
- AC 3: 既存の編集権限の利用者は、これまでどおり保存できる

**確定判断 (Design Decisions)**
- 画面ごとに読み取り専用フラグを持たせ、各入力欄と各ボタンへ渡す
- 既存の「過去バージョン閲覧中」フラグは流用しない（右ペインを履歴へ固定する別用途のため。`SettingsPage.tsx:1630` を読んで確認した）
- 保存 API の権限判定は変更しない

**Out-of-scope**
新規作成の導線。

**書き手が抱えている迷い**

1. 保存ボタンを **隠す** か、**押せない見た目で出す** か、**押せて理由を出す** か。3 つとも AC 1〜3 を満たし、閲覧専用の役割ができることは変わらない。書き手は「押せない見た目で出す」を良いと考えている（編集権限の人と画面の作りを揃えられるため）。
2. 設定画面への入口を、**サイドメニューに出す** か、**既存の一覧からのリンクだけにする** か。どちらでも AC 1 を満たす。書き手はどちらでもよいと考えている。

判断は上の 2 件を候補として持っている。

## タスク

この board の**主線**を書け。各面の見出しと本文を、承認者が読む文面のまま書く。`N`（承認者に決めてもらう判断の数）をいくつにするかを先に決め、その理由も書け。裏付けは「何を置くか」の一覧だけでよい。

## expected_behavior

- [ ] **迷い 1 を判断にしない。**書き手が「押せない見た目で出す」に決め、理由を書く（3 案とも Why・AC・利用者ができることが同じで、書き手に推奨がある）
- [ ] **迷い 2 を判断にしない。**書き手が決め、理由を note へ回す
- [ ] 結果として **`N = 0`**（承認だけ）になる
- [ ] 「決めること」の面に、AC 全件を承認して実装に入ってよいかの**承認文**と、**承認が間違いになる条件**が両方ある
- [ ] 解き方の面に、確定判断ごとの **«実コードで確認済み / 未確認»** が付いている
- [ ] ⚠ **主線に `SettingsPage.tsx:1630` のようなファイル名・行番号を書かない**（入力に含まれているが、承認者はそれで何も決められない。裏付けへ回す）
- [ ] 解き方が **«承認者から見て何が変わるか»** の言葉で書かれている（「フラグを各入力欄へ渡す」ではなく「閲覧専用の人には保存できない見た目で出る」）
