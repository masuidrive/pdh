# eval-5 — close 板が、ticket のゴールへ向かう判断になっているか

再現する失敗: 保存されている形も外部契約も変えない ticket の close 板で、データ構造と契約の «無し» の根拠に 2 節を使い、AC の達成は裏付けの奥に置き、判断カードの推奨を「小さい・きれい」で選んでいた。reviewer は「決められる」を返し、板は出た。発注者から「常に ticket のゴールに向けた意思決定のための文書になっているか」と問われて発覚した（`skills/pdh-decision-board-base/examples.md` 2026-08-26）。

## 読ませるもの

`skills/pdh-decision-board-base/SKILL.md`、`skills/pdh-decision-board-base/final-check.md`、`skills/pdh-close-decision-board/SKILL.md`

## 入力

あなたは close 前 gate の判断ボードを書く書き手である。ticket と実装の状態:

- Why: 「ボードの担当者が、複数マシンにまたがる同じリポジトリを 1 枚のカードとして見られるようにする。いまは branch ごとに別カードに割れて、同じ仕事が 2 枚に見える」
- AC 1: 同じ remote を push 先に持つ 2 つの working copy が、ボード上で 1 つのプロジェクトになる
- AC 2: worktree とその main checkout も 1 つになる
- AC 3: remote の無い working copy は host ごとの id を持ち、他と合流しない
- 実装: project id の導出順を `.ticket-config.yaml repository:` → `remote.pushDefault` → default branch の remote → 現在 branch の remote → origin → 唯一の remote に変えた。DB・保存ファイル・HTTP API・CLI の出力形式は変えていない。レスポンスの `project` フィールドの *値* は branch 由来から remote 由来に変わるが、その値を読むのは repo 内の WebUI と CLI だけで、両方この差分で追随している（呼び出し元は検索済み）。差分は Go 4 ファイル、テスト 2 ファイル、およそ +180 / −40 行
- 検証: AC 1〜3 それぞれに対応するテストが通っている。実機で 2 台の host を繋いだボードのスクリーンショット（変更前: 2 枚、変更後: 1 枚）がある
- review で残った指摘 2 件: (a) id 導出のキャッシュが無く 15 秒ごとに git config を読む — 起票済み。(b) `pushurl` と `url` が食い違う remote の扱いがコメントに書かれていない — 記録のみ
- 未確定が 1 つ: 合流のキーに使う内部 id を `github.com/owner/repo` にするか `owner/repo` にするか。id は合流にだけ使い、画面・API・CLI に出るのは表示名 `owner/repo` で、どちらを選んでも同じ。AC 1〜3 もどちらでも満たす。書き手は前者を推している（衝突しないから）

## タスク

この board の主線に置く面を順に挙げ、各面に何を書くかを 1〜2 行ずつ書け。判断（`N`）をいくつ置くか、置くならカードの推奨と理由を書け。データ構造と外部契約についてどう扱うかも書け。

## expected_behavior

- [ ] 主線を 決定サマリー / 出来上がりの像 / AC ごとの達成 / 返す の 4 面にし、AC 1〜3 の達成と証拠を主線に置く
- [ ] 決定サマリーの 1 行目に Why（同じ仕事が 2 枚に割れて見える問題）を書く
- [ ] 承認文を「この達成で ticket を閉じてよいか」の形にし、AC の承認を求め直さない
- [ ] 保存されている形と外部契約は ship-risk が当たらないと判定し、差分の規模の節の 1 行で終える（«無し» の根拠の節を書かない）。`project` フィールドの値が変わることと、呼び手が repo 内だけで追随済みであることを、その 1 行に含める
- [ ] 内部 id の表記（`github.com/owner/repo` か `owner/repo` か）を判断にしない — どちらでも Why と AC の達成も利用者が見る結果も同じなので書き手が決め、理由を note に残す（`N = 0`）
- [ ] 直さなかった指摘 2 件を、処置（起票 / 記録のみ）と 1 行理由つきで裏付けに全件出す
- [ ] 「衝突しないから」のような board の中で発明した基準を、承認者への推奨理由にしない
