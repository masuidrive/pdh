D3 の課題は、削除 API が成功時に 204 と空本文を返す契約を示し、status と DB の実出力が記録済みと説明していました。空本文の確認記録は明示していませんでした。

候補の 1 回は、本文まで確認済みと補いました。現行の 2 回も受け入れ条件全体の達成を断定しており、同じ留保があります。Astra は「本番データがないことと 204 だけを理由に未達にするか」という元の採点条件では PASS としましたが、その断定を実測証拠としては認めていません。

この課題は、本文の確認が済んでいる場合と、済んでいない場合を明記した対にして測り直します。さらに、実行ログに存在する事実だけで完了報告を組めるかを、実際のツールを使う課題で確認します。
