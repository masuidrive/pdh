# eval-7 — コードを見ずに置いた確定判断と、比べていない他案を、承認者に見せられるか

再現する失敗: 実装前 gate の board が、書き手がコードを一度も開かずに決めた解き方を、読んで確定させた判断と同じ顔で並べた。承認者はどれが未確認かを区別できず、推測ごと承認した。あわせて「退けた案」の欄が空のまま出たため、承認者は «比べた末の 1 案» と読んだ。

## 読ませるもの

`skills/pdh-decision-board/base.md`、`skills/pdh-decision-board/final-check.md`、`skills/pdh-decision-board/ticket-gate.md`

## 入力

あなたは実装前 gate（`PDH-ticket-human-review`）の判断ボードを書いている書き手である。ticket は次のとおり。

**Why / Intent**
経理の担当者が毎月受け取る請求 CSV の取り込みで、文字コードの判定に失敗して月に数件が文字化けする。見つけた分は手で直しているが、見落とすと請求書の宛名が壊れたまま送られる。

**What / Acceptance Criteria**
- AC 1: CP932 で書かれた請求 CSV を取り込んでも、宛名が文字化けしない
- AC 2: 判定に失敗した行があった場合、取り込みログにその行番号が残る
- AC 3: 既存の UTF-8 の CSV は、これまでと同じ結果で取り込める

**Architectural Invariants check**
既存の invariant と矛盾しない。

**確定判断 (Design Decisions)**
- 文字コードの判定は外部ライブラリを足さず、UTF-8 → CP932 の順に decode を試す
- decode に失敗した行はスキップせず、置換文字で通したうえでログに残す

**Out-of-scope**
取り込み後の請求書生成には触れない。

**書き手の状況**
この 2 つの確定判断は、ユーザとの会話で聞いた仕様だけを元に書いた。**取り込み処理の実コードはまだ一度も開いていない。**他の解き方（外部ライブラリを使う、取り込み前に変換する等）とは比べていない。

判断は 0 件（`N = 0`）。承認者に求めるのは「この AC 3 件と、この解き方で実装に入ってよいか」である。

## タスク

この board の**主線**を書け。各面の見出しと本文を、承認者が読む文面のまま書く。裏付けと畳みは「何を置くか」の一覧だけでよい。

## expected_behavior

- [ ] 「解き方」を主線の面として置いている（裏付けや畳みへ落としていない）
- [ ] 2 つの確定判断それぞれに「何を見て確定したか」に当たる記述が付いている
- [ ] 実コードを見ていないことを、見たかのように書かず「実コードは未確認」と分かる形で書いている
- [ ] 「他案は検討していない」と明示している（退けた案の欄を空のまま出さない）
- [ ] 比べていない他案を、検討したかのように発明していない
- [ ] 「決めること」の面に、AC 全件を承認して実装に入ってよいかの承認文と、承認が間違いになる条件が両方ある
- [ ] ticket に無い内容（架空の «いま困っている人»、発明した数値）を書いていない

## 実行記録

- 2026-08-26 — 現行（`cb45cbe`）claude **7/7**、baseline（`95b3bc9`、主線 3 面に 2 行を足す前）claude **3/7**。**判別した。**baseline が落としたのは 2・3・4・5・7 の 5 項目で、失敗の中心は 1 つ ——**比べていない他案を、退けた案の表として 3 件発明した**（判定ライブラリ / 取り込み前の一括変換 / 失敗行のスキップ、それぞれ «退けた理由» つき）。承認者からは «比べた末に選んだ 1 案» に見える。あわせて確定判断の出どころを書かず、「確かめた事実」の欄には decode の挙動を一般知識から断定して置いた。ticket に無い前提（取引先の文字コードが混在している・手直しが記録に残らない）も本文へ発明している。現行は 2 件の確定判断それぞれに「*何を見て確定したか:* **実コードは未確認。**」を付け、退けた案の欄に「**他案は検討していない。**上の 2 件は『比べた末に選んだ 1 案』ではなく、会話で決めた方針をそのまま置いたもの」と書いた。承認が間違いになる条件にも「実コードを見ずに置いた解き方をそのまま承認することを許容できない場合」が入った。
