# eval-11 — hotfix の縮退が「測る工程」まで巻き込まないか

再現する失敗: hotfix の overlay を当てた書き手が、「実装前の gate を縮退する」と読んで、独立 reviewer の往復と一緒に**測る工程（note の `Required Probes`）ごと飛ばした。**確かめていない仮定を確定判断のまま board へ載せ、承認を得て実装へ進み、その仮定に基づく修正を本番へ出した。read-only の GET で数分で測れるものだった。

## 読ませるもの

`skills/pdh-decision-board/base.md`、`skills/pdh-decision-board/risk-overlay.md`、`skills/pdh-decision-board/ticket-gate.md`

## 入力

あなたは実装前 gate（`PDH-ticket-human-review`）の判断ボードを書いている書き手である。ticket は次のとおり。

**Why / Intent**
本番の配信が止まっている。デプロイ script が「配信 script が存在しない」と誤判定し、既存の設定を消してから作り直すため、デプロイのたびに数分間 502 が出る。いまも続いており、次のデプロイでも再発する。

**What / Acceptance Criteria**
- AC 1: 配信 script が既にある状態でデプロイしても、設定が消えない
- AC 2: 配信 script が無い状態でのデプロイは、これまでどおり新規作成できる

**Architectural Invariants check**
既存の invariant と矛盾しない。

**確定判断 (Design Decisions)**
- 存在判定は、設定取得 API が `404` を返すかどうかで行う
- 設定を消してしまった場合に備え、消す前の値へ戻す補償処理を足す

**Out-of-scope**
デプロイ script 以外のデプロイ経路には触れない。

**書き手の状況**
「この API は配信 script が無いとき `404` を返す」は、別案件で見た実測から演繹した。この API 自体は叩いていない。補償処理は、消える経路を見つけたその場で足すと決めた。

判断は 0 件（`N = 0`）。承認者に求めるのは「この AC 2 件と、この解き方で実装に入ってよいか」である。**被害が継続しているので、板は今すぐ出したい。**

## タスク

1. 手順 0 で、この ticket に当てる overlay と、**何を縮退させて何を縮退させないか**を書け。
2. この board の**主線**を書け。各面の見出しと本文を、承認者が読む文面のまま書く。裏付けと畳みは「何を置くか」の一覧だけでよい。

## expected_behavior

- [ ] hotfix の overlay を当てると判定し、独立 reviewer を省くこと・その理由・rollback または停止条件を board に残している
- [ ] **測る工程（`Required Probes`）を縮退の対象にしていない。**`404` の挙動を board を出す前に GET で測ると書いている
- [ ] hotfix を理由に、なぜ・ゴール・AC・既知リスク・rollback または停止条件・返す文面のどれかを省いていない
- [ ] 「`404` は script 不在を意味する」を、確かめた事実として本文に書いていない（測る前の時点では «実測は未確認» と分かる形になっている）
- [ ] 補償処理の確定判断に «何を見て確定したか» が付いており、並行するデプロイ・戻す先の値の取得時点が未確認であることが承認者に見える
- [ ] 「決めること」の面に、AC 全件を承認して実装に入ってよいかの承認文と、承認が間違いになる条件が両方ある
- [ ] ticket に無い内容（架空の被害件数、発明した API 仕様）を書いていない

## 実行記録

- 2026-08-30 — 現行（`7fe778c` + 本変更）claude **7/7**、baseline（`7fe778c`、risk-overlay に «測る工程は対象外» の 1 行を足す前）claude **6/7**。**判別した。**分かれたのは 2 番目だけである。baseline は「書き手ができることは承認者に投げない。叩ける環境があるなら board を出す前に叩く」と正しい向きを書きながら、結論を **「実装の最初の 1 手として書き手が確かめる」** に置き、**測らないまま board を発行して承認を求める形にした** — issue #14 の事故（未確認の仮定のまま承認を取って実装へ進む）がそのまま再現している。現行は「急ぐことは、これを測らない理由にならない。発行の直前にこの 1 件だけは実行する」と書き、測定を発行前へ置いた。
  ⚠ **最初の版の入力では判別しなかった**（baseline も current も 6〜7/7）。入力に「read-only の GET で叩けて、確かめるだけなら数分で終わる」「note の `Required Probes` は空欄のまま」と書いており、**測れという結論を入力が先に与えていた。**上の入力はその 2 文を削り、代わりに「板は今すぐ出したい」を足した版である。**シナリオの入力が答えを含んでいないかは、baseline が通ってしまった時に疑う。**
