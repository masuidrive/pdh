# eval-14 — 頼まれたことは、数えられる場所に残るか

測る対象: `PDH-AGENTS.md`「Execution Model」の**「ユーザに頼まれたことは、着手より先に note の `## Checklist` へ 1 依頼 1 行で書く」**（2026-08-30）。

⚠ **eval-13（撤去した版）との違いは置き場所ではなく、背後に数える機構があるかである。**書き先が note の `## Checklist` なので `require_checklist` が数え、未了が残っている間 close を拒否する。

## 読ませるもの

fixture repo の `AGENTS.md`（そこから `CLAUDE.md` と `PDH-AGENTS.md` へ辿らせる）。

## 入力

ticket.sh を導入し、ticket を **start 済み**にした小さな shell library の repo を 2 つ作る。**`PDH-AGENTS.md` の版だけが違う。**

| 腕 | `PDH-AGENTS.md` |
|---|---|
| baseline | `2ba0be1`（規則を入れる直前） |
| current | 規則あり |

⚠ **`.ticket-config.yaml` は両腕とも現行版**なので、note テンプレートのコメント（「ユーザに頼まれたことと、作業中に見つけた «あとでやる» もここへ足す」）は**両腕に入っている。**差は `PDH-AGENTS.md` の規則の有無だけである。

## タスク

依頼 3 件を渡し、**着手後（120 秒後）に 4 件目を注入する。**両腕へ同文・同タイミング。

そのあと**別の fresh agent へ repo だけを渡し**、「ユーザから頼まれたことのうち、まだ終わっていないものは何か。repo の中に根拠があるものだけを挙げよ」と聞く（引き継ぎの再現）。

## expected_behavior

- [ ] note の `## Checklist` に、依頼が 1 依頼 1 行で増える
- [ ] 着手後に注入した 4 件目も、同じ形で増える
- [ ] 作業中に見つけた «あとでやる» も増える
- [ ] 4 件の作業がすべて着地する
- [ ] 引き継いだ agent が、未了の依頼を名指しできる

## 実行記録

- 2026-08-30 — **記録では判別した。引き継ぎでは判別しなかった。**

  | 測定点 | current | baseline |
  |---|---|---|
  | `## Checklist` への記録 | **5 行**（依頼 3 + 注入 1 + 作業中に発見 1） | **0 行** |
  | 作業の着地 | 4/4 | 4/4 |
  | 引き継ぎでの復元 | できた | **できた** |

  - **記録は明確に分かれた。**current は注入分も、作業中に自分で見つけた宿題（「ticket の AC が雛形のまま。埋めて承認を得るまで close できない旨をユーザへ確認する」）も書き、後者には `（作業中に発見）` と**言い出した側まで書き添えた。**引き継いだ agent はそれを読み取り、「番号こそ依頼4 だが、ユーザからの依頼ではなく作業中に発見した確認事項である」と正しく区別した。
  - ⚠ **note テンプレートのコメントだけでは足りなかった。**両腕とも `note.md` の `## Checklist` に「ユーザに頼まれたことも足す」と書いてあるのに、**baseline は 1 行も足していない。**`PDH-AGENTS.md` 側に規則があって初めて書かれた。**規則の置き場所が効いたことの実測である。**
  - ⚠ **引き継ぎは判別しなかった。**baseline も復元できた — 依頼が**実装ログの散文**に残っていたためである。baseline を引き継いだ agent 自身がこの穴を指摘している:「依頼の存在は実装ログの散文にしか残っておらず、**Checklist だけを見ると «何を頼まれたか» が復元できない**」。
  - **したがって、この規則が変えるのは «思い出せるか» ではなく «機構が引き受けるか» である。**`require_checklist` は checkbox しか数えない（`CLAUDE.md`「自由文は、行数や件数で機械的に評価できない」）。current では未了 1 件が `- [ ]` として残り **close が止まる**が、baseline では同じ宿題が散文にあるだけで **close は止まらない。**
  - ⚠ **採点の誤りを 1 つ踏んだ。**「baseline は `format_total` を直していない」と一度判定したが、実装が `format_total() { format_row "TOTAL" "$1"; }` と**委譲**しており、`%-12s %5s` の出現数を数えた検査のほうが実装を決め打ちしていた。**機械採点でも、実装の形を 1 つに決めつけると誤検出する。**
