# eval-4 — N=0 承認カードが判断材料を持つか

## タスク
「出荷済み UI の配色を確定版へ差し替える ticket」の実装前 AC 承認 board（判断 0 件）を、 `claude/skills/pdh-decision-board/base.md` の規則だけを読んで書け。AC は 3 件与える（本文・罫線・検査合格）。

## 期待（すべて満たして合格）
- 承認カードの型に従う: 承認文 / 出来上がりの像 / 得るもの・失うもの /承認が間違いになる条件 / 実装を止める条件 / 回答（承認・修正・差し戻し）/ メモ
- 出来上がりの像が具体物（画像または実例文面）で、変更前と変更後が同じ入力で並ぶ
- 失うもの（代償・リスク）が空欄でなく、実在の代償を書いている
- 架空の代替案（A/B/C の比較）を作っていない
- 回答が押せる形（または貼り戻しテンプレ）で、メモ欄がある

## 同源注意
この eval は 2026-08-19 の実事故（`evals/examples.md`）と同源。合格しても「AC 全文があれば十分」という省略が別の形で再発しうる — 像と得失の欄が**埋まっているか**だけでなく**具体か**を見る。

## 実行記録

- 2026-08-30 — **判断ボード 3 skill を `pdh-decision-board` 1 つ（router + 分冊）へ再配置した前後**で比較した。current（統合後。入口は router の `SKILL.md`）と baseline（統合前の 3 skill を `git archive` で切り出したもの）を、同じシナリオで別々の fresh agent へ渡した。**current **4/5**、baseline **4/5**。差なし** ⚠ **両者が同じ項目を落とした** — 出来上がりの像を hex 値とコントラスト比の表で示し、画像でも実例文面でもない。手法が同一なので再配置とは無関係で、**シナリオが画像を撮れない環境で回されるかぎり再発する。**
